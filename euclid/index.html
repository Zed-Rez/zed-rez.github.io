Autoformalization · Lean 4

Can an AI rewrite Euclid into a language a computer can check?

And if it can, what actually makes it succeed — the wording of the math, or how you ask?

The problem

A proof in a textbook is written for humans. Lean 4 is a language a computer can verify line by line — if a Lean proof compiles and checks out, it is correct, no trust required.

Translating ordinary mathematical prose into Lean by hand is slow expert work. The hope is that a language model can do the translation — "autoformalization." This study asks a narrow, testable version of that question, using Euclid's Elements as the source.

The source material

Euclid's Elements, Book I — the same 48 propositions — exists in very different English registers. We used three:

  • Heath (1908): archaic, Victorian phrasing.
  • Fitzpatrick (2007): modern academic, with variables named explicitly.
  • Modern: a plain contemporary paraphrase.

All three say the same things. The question: does the English register change how well GPT-4o formalizes the proposition into Lean? We built on the LeanEuclid benchmark (Murphy et al., 2024).

The trap we fell into first

An early run used one prompt template whose five worked examples were all written in Fitzpatrick's style. It looked like Fitzpatrick text formalized best — beating Heath by 8.4 percentage points (p=0.008).

But that confounded two things. The Fitzpatrick translation matched the examples in the prompt. We couldn't tell whether the text register mattered or whether the model just liked input that looked like its examples.

The fix: a counterbalanced design

To separate the two, we crossed them. Three translation registers × three prompt styles (Fitzpatrick-style, Heath-style, Modern-style examples) — a fully crossed 3×3 design over 143 propositions (Book I plus 100 UniGeo theorems), 2,653 total runs.

Now every translation gets tested against every prompt style, so the two effects can be pulled apart.

The result

How you prompt matters. Which translation you feed in does not.

Prompt style swung the compile rate across a 24-point range — 72.6% with the best style vs. 48.4% with the worst (p<0.001). Translation register had no significant effect once prompt style was held fixed (p=0.603).

The statistics

A mixed-effects regression (proposition as random intercept, N=2,653) confirms it: translation coefficients are tiny and not significant; prompt coefficients are large and significant.

Adding prompt style improves model fit by 99.5 AIC points; adding a prompt×translation interaction does not help (AIC rises 4.3). A paired t-test on per-proposition rates (N=66, marginalized over prompt) leaves Heath and Fitzpatrick statistically indistinguishable: 70.0% vs. 62.3%, t(65)=−1.66, p=0.102, Cohen's d=−0.20.

The caveat: a model that cheated

We first tried a small local model, Qwen2.5-Coder-7B, running on a Jetson Orin Nano Super (8GB, ~9.5 tokens/sec). It had memorized the benchmark. Its best compile rate came from giving it no math at all — just "Proposition N":

Highest score from empty input means the model is reciting memorized structure, not reading the math. (Semantic equivalence does drop to 0% on empty input vs. 16–27% with garbled text, so it reads input to refine meaning — but it doesn't need it to produce something that compiles.) For comparison, GPT-4o is clean: 10% from empty input vs. 67.9% from full text. We dropped Qwen and ran everything counterbalanced on GPT-4o.

What this means in practice

If you want to use autoformalization on your own mathematics, the lever isn't cleaning up your prose — it's styling your few-shot examples to match how you write, especially whether they introduce variables explicitly.

Two methodological notes fall out of this. First, a single prompt template can manufacture a fake "wording" effect, so counterbalanced prompt designs should be standard. Second, the empty-input probe — does the model compile from just "Proposition N"? — is a cheap memorization check worth running before anyone reports autoformalization numbers.

Honest limits

  • One model. The counterbalanced results are GPT-4o only; the Qwen runs are void due to contamination. Prompt sensitivity may differ elsewhere.
  • Compiling isn't being correct. Compile rates overstate real performance. On the subset semantically scored: 14% strict equivalence, 30% correct-direction. The 24-point prompt effect is measured on compilation, not correctness.
  • Uneven cells. Fitzpatrick-prompt cells carry 430 runs each; Heath and Modern prompt cells have 133–235. The model handles the imbalance, but precision varies.
  • UniGeo, one prompt. The 100-theorem replication used only Fitzpatrick-style prompts, so it confirms the translation non-effect but not the prompt effect.
